## Theory

A socket is basically an end point of a two-way communcation link between two programs running on a network. We use the sockets to establish communication and data transfer between two programs. Typically following the *Client ↔ Server* communication. 

In this tutorial we'll specifically go over WebSockets and not Traditional Sockets. Traditional Sockets are outdated and inefficient especially in wireless communication where WebSocket Shines, *I'll still provide a basic tutorial on Traditional Sockets as it is easier to tinker with*


## Key Differences

| Traditional Sockets | Web Sockets |
|---------------------|-------------|
| Lower Level | Higher Level Protocol|
| Often Requires Custom Protocols | Works over HTTPS, firewall friendly |
| Manual Encoding/Decoding | Automatic Encoding/Decoding |
| Linear/One Way | Asynchronous |
| Manual Handling | Auto handling ping/pong |

WebSockets are best used for Web-Based Real-Time Communication; Raw Sockets are used when Building system-level communication for non-browser environments.

## Netowrking Terminologies

| Term | Meaning |
|------|---------|
| Client | The Device/Application that Initiates a Connection (eg: Browser) |
| Server | The system that listens and responds to client's requests |
| IP Address | A Unique identifier for a device on a network (eg: 192.168.1.1) |
| Port | A communication end point, the specific access point of the communication link (eg: 80 for HTTP, 443 for HTTPS)|
| Handshake | The process by which a connection is established |
| Packet | Smallest Unit of Data sent across a Network |
| Socket | End point of communication link, a combination of IP & Port that allows other devices to locate and communicate |
| Binding | Assigning a Specific IP and Port to a Socket |
| Listening | A server's state of waiting for incoming data |

## Websockets in Python

Almost Every program in Websockets are done with Asyncio. As the time taken to do any certain activity over a network is uncertain and a blocking code quickly fails for networking programs, hence the program is meant to be asynchronous

### Server Start

```python
import websockets
server = websockets.serve(handler, 'localhost', 8765)
```

The `serve` function creates a Server for Clients to connect to, the function takes three arguments.
1. Handler: It's a function to which the Clients Socket is send to as it connects. Basically a Setup function of Client
2. Host: The Host to connect to, for local purposes used 'localhost' otherwise enter connecting IP
3. Port: The Port to connect to within Host

The address of Host and Port can be written in WebSocket (ws) form too -> 'ws://localhost:8765'

### Connect Client

```python
import websockets
async def connect():
    async with websockets.connect("ws://localhost:8765"):
        pass        
```

Uses `async with`, a with statement basically Groups a Connection to a URL/FILE/DATABASE and handles error and closing all by itself saving us hassle. An `async with` does the same just allows async commands within.

`websockets.connect(url)` is the statement used to connect to server which returns the client Socket

### Send and Receive Data

`await weboscket.send(data)` & `await websocket.recv()`

If ran by Client, the data is sent/received to/from Server.
If ran by Server, the socket should be of the Exact Client you want to transfer data with

### Close

If not using with statements, you must manually close the socket once work is done
`clientSocket.close()`

Much like closing a file, this closes a socket



## Traditional Socket Tutorial

*Now that you know WebSockets, I am gonna go over a quick and fast cover on Socket Syntax*

Socket is a built-in library unlike web-sockets and easier to use for beginners.

1. Create Server/Client: `server = socket.socket(<Protocol>, <Stream>)`
2. Bind Server to IP: `server.bind((<host>, <ip>))`
3. Connect Client: `client.connect((<host>, <ip>))`
4. Sever Start: `server.listen()`
5. Data Send and Receive: `send()` & `recv()`

Do Remember Traditional Sockets Require MANUAL encoding and Decoding of Data, here's an example server and client code:

SERVER:
```python
import socket

server = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
server.bind(('localhost', 12345))
server.listen()

#Establish Connection
conn, addr = server.accept()

#Accept Data
data = conn.recv(1024).decode()

#Broadcast Data
conn.sendall(data.encode())

conn.close()
```

CLIENT:
```python
import socket

client = socket.socket(socket.AF_INET, sock.SOCK_STREAM)
client.connect(('localhost', 12345))

client.send("HELLO".encode())

data = client.recv(1024).decode

client.close()
```

## REAL WORLD USE

Server:
```python
import asyncio
import websockets

clients = []

async def handleClient(clientSocket):
    clients.append(clientSocket)

    #Receive any data sent by Client the Moment any data does come, stay paused otherwise
    async for message in clientSocket:
        print(message)
        clientSocket.send("Hello Client")


async def main():
    async with websockets.serve(handleClient, 'localhost', 8765):
        print("SERVER IS ON")
        await asyncio.Future()

asyncio.run(main())
```

Client:

```python
import asyncio
import websockets

async def connect():
    async with websockets.connect("ws://localhost:8765") as clientSocket:
        await clientSocket.send("Hello Server! ")
        response = await clientSocket.recv()
        print("Server: " response)

asyncio.run(connect)
```

*If you are confused as to why we have a handleClient function for server, but no handleServer function for client. A client connects to just one server so it's one way, but a server can connect to Many Clients, hence the handleClient function allows us to connect to every client and run the function seperately for each client*
