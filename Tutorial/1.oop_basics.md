## Theory

OOP is *Object-Oriented-Programming*. It is the Fundamental of Modern Programming, before teaching you what it is, let me give you a Hint of how Important this is. The most influential programming Language is arguably **C**, it came out before OOP. OOP transformed coding so much that people had to get together to upgrade C, which resulted in **C++**, the whole purpose of C++ the modern Tank of a language was to have Object-Oriented Programming within C.

Now, what is Object Oriented Programming? Well, it is *Blueprints* basically. Basically entities, instead of having functions floating around you can group them, it's highly used for organization. You HAVE used Object Oriented Programming, just you haven't created your own Objects. Lists, Tuples, Strings, Ints, etc, we call them Data Types, but **all Data Types are merely an Object**. *OOP is the treating of different components of a Program as Different OBJECTS*.

Just like you can you have as many Ints and Strings, of any given object you make, you can have countless of them.

Let us understand the Concepts of OOP, then the Syntax.

### Key Concepts:

1. Classes: Classes are the Blueprints of every Object, the very core of OOP. When you define a Class, you define an object with its properties and all. So each seperate object within a program is called a Class [Object & Class are used interchangebly but Class is preffered]

2. Instances: For one given class, say you have two variables using the blue print of the Class. So these two variables are storing two objects which are mostly similar except for some modifications you might create. **Each variable is then an Instance of the Object**

3. Attributes: Variables defined within Classes are called Attributes, these are like Properties of the given Object which you can modify per *Instance* of the object. 

4. Methods: Functions defined within Classes are called Methods, these are functions that allow the Class to function and are *share with all instance as same.*

5. Modularity: Seperating Different purposes of your program to different Classes makes code Readable and much easier to modify in the futurer

6. Inheritance: **Arguably the MOST important one**. You can make sub-classes, Parent & Child Classes. This is very interesting yet complex and beyond the scope of the tutorial. If interested you can look into it. It is mostly used in Developing Games


Let's take an example, OOP's are easily explained via Games. Imagine a Racing Game, so say for different cars, instead of original code for each car it's better to use classes. You won't have to copy-paste the same code and modify it for each car, you can make a car blue-print.

A class named Car. It can have the Attributes of 'Engine', 'Speed', 'Acceleration', 'Tires', and etc. It can have the Methods 'startCar()', 'brakes()', 'drift()'.
Now for different cars, you can create instances of the above class and then just modify the attributes, a Toyota may have higher speed than a Jeep but slower acceleration.

Let us Learn the Syntax

## Syntax

### Classes

To Create a class, you need two things,
1. Class Name
2. Initilization Method

```python
class Car:
    def __init__(self):
        pass
```

Let us understand this line by line,
`class Car`: This line creates a New Object called 'Car', very simple, much like defining a function.
`def __init__()`: This line is very important. You create a new method [or function, but functions in classes are called methods], this is called the 'Initilization Method'. *When you Create any Instance of this class, this method will run AUTOMATICALLY*.  Basically a setup function, used to define all the attributes within the class.
`self`: The parameter given to Every Method, and used with Every Attribute. The most used Keyword within classes. Basically, self means the Instance itself. **This is confusing but first go through the syntax upto INSTANCES, then there's detailed explanation on self and read these again to clear doubts**


### Attributes

Attributes are the variables assosciated with the Class. Not all Variables in a class are Attributes, how do we differentiate? 

```python
class Car:
    def __init__(self):
        self.speed = 20
        self.acceleration = 5
        i = 0
```

In this code, the 'speed' & 'acceleration' are the Attributes, but i is a normal variable. **Any variable used with self. is an attribute**. What's the differene? When you instance the class, that is have objects using this as blueprint, they can access and modify the speed & acceleration but not 'i'. Attributes are Modifiebale and Universal variables,

### Methods

Methods are All and Any function defined within a Class

```python
class Car:
    def __init__(self):
        self.speed = 20
        self.acceleration = 5
        i = 0

    def brake(self):
        self.acceleration = -5
```

The function `brake(self)` in there is a Method. **Every method MUST have 'self' as their first Parameter**. Methods are functions that instances can use anytime easily.

### Instances

You learned how to make a blueprint, let's use the blue print to make some objects and then EVERYTHING will click.

```python
class Car:
    def __init__(self):
        self.speed = 20
        self.acceleration = 5
        i = 0

    def brake(self):
        self.acceleration = -5

toyota = Car()
jeep = Car()

toyota.speed = 30
jeep.acceleration = 20

jeep.brake()
```

`toyota=Car()` & `jeep=Car()` created two Instances of the Car class named toyota and jeep. To create an instance we just name the class and call it like a function

`toyota.speed=20` & `jeep.acceleration=20`, if you see above you can see that the class has two attributes speed and acceleration, using this we modify the speed of toyota and the acceleration of the jeep. *If you try to do the same with 'i', you'll get an error as that is NOT an attribute*.

`jeep.brake()`, calls the Brake method for jeep, but not for Toyota. So the Acceleration of Jeep changes to -5, but the Toyota remains unchanged

So you can see, this way we can have multiple objects sharing basically same code but changes in one doesn't interfere the Other!

Now, you have seen the syntax use of self but it might still be confusing, let us go over it

### SELF

Self basically is a substitute for the Instance.

Take example above, we called `jeep.brake()`, the method brake being:

```python
def brake(self):
    self.acceleration = -5
```

In this method, it says `self.acceleration = -5`. **Basically self states that the given attribute is UNIVERSAL to all instances and Independent**. Any attribute that doesn't use Self or a method that doesn't use self won't give errors, but they won't be accessible from outside the class by the Instance as they aren't Universal, those are generally used for technical code that the Object need not Access.

```python
def __init__(self):
    self.speed = 20
    self.acceleration = 5
    i = 0
```

In this, speed and acceleration are two variables that whenever any Instance of the class is Created. So when you do `toyota.speed=30`, the value of Speed attached to the Toyota is modified.


In a Nutshell, self means the Instance itself. Whenever an instance is created, Attributes and Methods [Variables with self & functions with self] are attached to that Instance, and that instance can use them anytime. When an Instance uses a Method, the `self.` everywhere in that method is replaced by the Instance itself, so the `self.speed` would refer to that specific Instances speed. That's why `jeep.Brake()` referred to the Jeep's Acceleration due to `self.Acceleration`. Self is used to differentiate different copies of the same Object
