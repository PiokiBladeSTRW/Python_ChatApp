## Theory
Async Program (or Asynchronous Programming) is non-sequential programming. In simple words, it lets your code handle multiple tasks at once. Basically *multi tasking* in programming, while doing Task A program also does Task B.

---

When studying about Async, you need to know of something called Threading, both perform the same thing but with different methods.

**Threading is True Parallel Processing**, it runs two seperate Tasks really Together. Imagine two functions A() & B(). Using Threadings, you instruct the CPU that while it is running A() it should also run B() and that nothing happening in A() should stop B().

Async is half Parallel Processing, take an example code below to understand this:

```python
def Message():
    while True:
        Msg_To_Send = input()
        Send(Msg_To_Send)

def Receive():
    while True:
        Msg_Received = Read() 
        print(Msg_Received)
```

Imagine a chat app where users can *send* and *receive* texts, you don't want to stop receiving texts while user is typing something and vice versa. **You want to run Message() & Receive() Together.** In such cases of using two processes together we go to either Threading or Async.

### Primary Difference:

How is Async different? Threading **constantly** runs both processes, Async is smarter, it runs one process and as soon as one process is Idle, it goes to another. In simple words, Async is running **Either One of Message() & Receive()**, say it is running Message(), the millisecond Message() is doing nothing it goes to Receive() and the millisecond Receive() is idle it goes back to message. Async is arguable trickier to use but it saves LOTS of CPU & Memory why smartly handling processes. You'll understand more as we progress

Thraeding: Useful for Complex Algorithms & True Parallel Processings. 
Async: Useful for Communication and Back-&-Forth Algorithms.

Do know we most often use them together slightly, a Program can be **Mostly Threaded and still use Async** or be **Mostly Async and still use Threading**. You should use the one that suits your needs and don't be afraid to merge them together.

### Creating Co-routines


To create a Co-routine, put the `Async` keyword before `def`, as:

```python
async def hello():
    pass
```

Now *hello()* is a Co-routine!!

### Pausing Co-Routines

For Async to switch from one co-routine to another, there needs to be a pause within

To Pause, we use `Await` keyword. For now I'll give a simple example:

```python
async def hello():
    await asyncio.sleep(3)
    print("Hello")
```

This is important, what the function does now, is Wait *3* seconds before printing *Hello*. Let's go over this

`await asyncio.sleep(3)`: In this statement, asyncio.sleep() is a Function of Asyncio Library, it Pauses the Code for given time. Smart coders may remember python's Time library having 'time.sleep()'. The difference is that, time.sleep() **BLOCKS the code** for given time, and asyncio.sleep() **PAUSES the given Co-routine** for given time. But the *Magic is Await*.

Await is Used before *calling ANY co-routine*, this includes functions of the asyncio library and co-routines made by you. 
**!!NOTE: await can ONLY be used Inside a CO-ROUTINE. Your function needs have async before Def to use AWAIT in the function**

To avoid complexity, Await returns what's called a Future [Called Promise in other Languages]. Basically when you await a co-routine, the code waits for the given function to finish, it is *promised* of something to wait for, it holds the code from closing until the given function is finished. And while it waits, Async uses the time to run Other Co-routines, causing **multitasking**

### Starting Co-Routine

So, to make a Co-routine you need to put `async` before `def`. But to call any co-routine you need to use `await`, and you cannot use await outside an `async` function?! Confusing right?

That's why there is ONE single Function that does Not need to use 'await' [As we call, needs not be awaited].

```python
asyncio.run(hello())
```

This function can be put anywhere, and it doesn't have to be awaited, using this you can start your co-routines.

### Parallel Tasks

For the sake of Example, suppose you have two Co-Routines *Message() & Receive()*, and you wanna run them both, there's two criteria:

1. Both Functions need to have *Await somewhere within them*, otherwise Async will never go to other function
2. Both Functions need to have been called **TOGETHER**

How to call Functions Together? `gather`, here's an example how to use:

```python
async def main():
    await asyncio.gather(Message(), Receive())

asyncio.run(main())
```

`gather` needs to be awaited, so we have to put it in an async function. And then we can call that function via run. This starts running Message() & Receive() *Parallel*

### Other Small Functions

1. Future(): Very Helpful functions, when you wanna keep your code running even if every co-routine is IDLE, put the following command in the main function: `asyncio.Future()`. This is basically an empty `while True:` that keeps the code running but with 0 CPU used

2. to_thread(): This is used to create a Thread within Async; That is, using threading and Async together. For example, the function `input()` is a *Blocking Function*, it stops Entire Code and doesn't care for co-routines. To run this along with co-routines, we make it a seperate thread, so the CPU handles this and the rest of code seperately. To use it do: `asyncio.to_thread(input)`. *Where 'input' is any function you want to thread*

3. async loops: You can create co-routines by putting async before def, but you can also make asynchronous loops: `async for message in client`, unlike traditional for loops, this won't *block the code*, what this does is run the loop ONLY when there's something to run. Imagine client is an empty list which randomly gets variables. What this does is wait for client to get a value and as soon as it does, it runs loop like usual only for client to be empty again. You can also use `async with` for asynchronous with statements

4. asyncio.Lock(): A Lock statement used to temporarily stop Asynchronous programming and allow program to be blocked. This is beyond our scope but store the Lock and use it for Critical Functions; store by `lock = asyncio.Lock()` and use by `async with lock`

5. Common Errors: Forgetting to await a Coroutine

## REAL WORLD USE
```python

import asyncio

async def dataFetch():
    print("Start")
    await asyncio.sleep(3) #Imagine Fetching Data that takes 3 seconds
    print("End")

async def display():
    for i in range(10):
        print(i)
        await asyncio.sleep(0.5) 

async def main():
    await asyncio.gather(dataFetch(), display())

asyncio.run(main())
```

Try running the code, you'll see Two Functions run Together
